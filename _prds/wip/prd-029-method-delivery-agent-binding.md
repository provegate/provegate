## 1. Introduction / Overview

The package ships ten phase protocols in `packages/provegate/prompts/`. **No agent reads
them.** They are published in the npm tarball (`package.json` `files`) and they are never
installed into a consuming repository: `PACK_MAP` in `core/run/init.ts` maps the practices
pack — `_brain`, `AGENT_BOOTSTRAP.md`, `STATUS.md`, hooks, `scripts/verify/` — and no entry
names `prompts/` or `templates/`. An adopter's copy therefore lives in
`node_modules/provegate/prompts/`, which no agent's file reader is pointed at.

This repository has the same gap in its own checkout, and the consequences are observable.
`prompts/phase-3-task-generator.md:92` carries the rule **"STOP — Do not continue until the
user says 'Go'"**; agents working here generate task plans without it, because the file is
never loaded. The only always-loaded phase guidance is `AGENT_BOOTSTRAP.md`'s
stop-and-ask list — nine reasons to STOP, two of them open-ended judgment calls
("out-of-scope files", "unspecified design question") — with no counterweight anywhere in
context saying that Phases 4–7 run without asking. The loaded context is asymmetric, so
agents both skip the human gates and invent new ones.

The parent project did not have this gap. The source snapshot preserves the mechanism:
`docs/research/provegate-bootstrap/source-snapshot/rules/prd-workflow.mdc` is a
glob-attached rule (`globs: _prds/**/*.md, _readiness/**/*.md, _tasks/**/*.md`) that maps
each phase to its prompt file, and four sibling rules do the same per phase. **Extraction
carried the method and left the delivery mechanism behind.**

This PRD builds the delivery mechanism as a first-class CLI capability: a rendered,
tool-neutral protocol store in the consuming repository, thin per-tool adapters that point
into it, a ledger that keeps the render honest, and a check wired into the gate bundle.

The prompts cannot be copied — they carry 21 placeholder tokens
(`{{CMD_TEST}}`, `{{ARCHITECTURE_DOC}}`, `{{BASE_BRANCH}}`, …) that `PLACEHOLDERS.md`
declares and half of which map to `workflow.config.json` fields. A raw copy hands the agent
`{{CMD_TEST}}` and no way to resolve it. Delivery is therefore a **render**, and
`core/run/new.ts:112-149` already renders the PRD template the same way.

## 2. Goals

### Primary Goals

- [ ] Every phase protocol reaches the agent's loaded context in a consuming repository,
      resolved against that repository's `workflow.config.json`.
- [ ] One protocol, one location: adapters carry a pointer and zero protocol prose, so a
      corrected rule cannot survive in a stale restatement.
- [ ] The rendered store is machine-checkable — divergence from the render is a named
      failure, and an intentional edit is a recorded, expiring exception.
- [ ] The `AGENT_BOOTSTRAP` entrypoint states the Phase 4–7 proceed rule, not only the
      STOP rules.
- [ ] Phase 3's autonomy exception becomes configuration the human sets, not a mode the
      agent grants itself.
- [ ] This repository consumes its own output — the binding is generated by the shipped
      CLI and committed, not hand-written.

### Success Metrics

| Metric                                                 | Current | Target | Measurement                                                          |
| ------------------------------------------------------ | ------- | ------ | -------------------------------------------------------------------- |
| Phase protocols reachable in a fresh `gate init` repo   | 0 of 10 | 10     | `gate doctor --prompts` on a scratch repo built by `gate init`         |
| Agent-config files pointing at a phase protocol         | 0       | 3      | generated adapters present for Claude Code, Cursor, Codex             |
| Protocol prose duplicated outside the rendered store    | n/a     | 0      | adapter bodies contain a path and no protocol text; asserted by test  |

## 3. User Stories

#### User Story 1

```
As an adopter who ran `gate init --practices`,
I want my coding agent to load the phase protocol for the phase it is in,
so that the gated method I installed is the method my agent actually follows.
```

**Acceptance Criteria:**

- [ ] After `gate init --practices --prompts`, the repository contains a rendered protocol
      store and one adapter per configured agent tool.
- [ ] Every rendered file resolves every placeholder from `workflow.config.json`; a token
      with no configured value fails the render by name rather than shipping literally.
- [ ] No pre-existing agent entrypoint (`CLAUDE.md`, `AGENTS.md`, `.cursor/rules/brain.mdc`)
      is overwritten, shadowed, or reordered.

#### User Story 2

```
As the maintainer of a repository that installed the protocols months ago,
I want to know when my store no longer matches the package I have installed,
so that a method upgrade does not silently leave my agents on the old protocol.
```

**Acceptance Criteria:**

- [ ] `gate doctor --prompts` re-renders in memory and reports every file that diverges.
- [ ] An intentional local edit is accepted only as a ledger exception carrying an owner,
      a reason and a review date; an unrecorded edit fails.
- [ ] An exception whose review date has passed fails, and so does one naming a file the
      render no longer produces.
- [ ] An absent protocol store on a configured repository **fails**; it does not skip.

#### User Story 3

```
As an implementing agent in Phase 4,
I want the entrypoint to tell me when to proceed as clearly as it tells me when to stop,
so that I neither skip a human gate nor manufacture one.
```

**Acceptance Criteria:**

- [ ] `AGENT_BOOTSTRAP.md` states that during Phases 4–7 the only legitimate stops are the
      listed stop-and-ask checkpoints and a failed gate.
- [ ] The same clause is in the shipped `AGENT_BOOTSTRAP.template.md`, so adopters get it.
- [ ] Phase 3's STOP rule renders without a self-granted exception when the repository is
      configured human-gated.

## 4. Functional Requirements

Each FR carries the exact target paths the implementing agent will touch. Use
`path/to/file.ts::SymbolName` notation for symbol-level targets.

1. **FR-1**: `WorkflowConfig` gains a `prompts` block: `dir` (string, default
   `.provegate`), `autonomy` (`human-gated` or `autonomous`, default `human-gated`),
   `adapters` (ordered subset of `claude-code`, `cursor`, `codex`; default all three), and
   `values` (`Record<string, string>` supplying the placeholder tokens that no config field
   maps to). Validation refuses an unknown adapter identifier, a non-string value, and a
   `dir` that escapes the workspace root — the escape check compares a realpath'd candidate
   against a **realpath'd** root, so a repository whose root sits behind a symlink is not
   refused. Absent `prompts` means the feature is off and every other FR is inert.
   - **Targets:** `packages/provegate/src/core/config/types.ts::WorkflowConfig`,
     `packages/provegate/src/core/config/types.ts::PromptsConfig`,
     `packages/provegate/src/core/config/defaults.ts`,
     `packages/provegate/src/core/config/load.ts`

2. **FR-2**: `renderPrompts(packageDir, config)` returns a `Map<string, string>` of
   repo-relative path to rendered content. The layout is fixed and flat, mirroring the
   package's own basenames so a reader can move between the two without translation:
   `<prompts.dir>/prompts/<basename>` for all ten files under the package's `prompts/`
   (including `PLACEHOLDERS.md` and `orchestration-runner.md`), and
   `<prompts.dir>/templates/<basename>` for the artifact templates. **`prompts.dir` holds
   generated output only** — every path under it except `provegate.lock.json` is produced by
   this function, and that totality is what lets FR-7 ask "does this tree match the render"
   as a complete question rather than a partial one. `workflow.config.json` is the render's
   **input** and stays at the repository root; it is never moved, copied, or emitted into
   the store. The function is pure — no filesystem writes, no clock, no environment read —
   so the same package version and the same config always produce the same bytes. Every
   emitted file opens with a generated-file banner naming the package version and the
   command that reproduces it.
   - **Targets:** `packages/provegate/src/core/run/prompts.ts::renderPrompts`,
     `packages/provegate/src/core/run/prompts.ts::storePath`,
     `packages/provegate/src/core/run/prompts.ts::GENERATED_BANNER`

3. **FR-3**: The render refuses when any output still contains a `{{TOKEN}}` sequence,
   naming each surviving token and the `prompts.values` key or config field that supplies
   it. The refusal is proved against the **shipped prompt corpus with an empty `values`
   map** — a fixture that passes only because the token happens to be absent from a
   hand-written sample proves nothing, and the tokens live in the very files this feature
   ships.
   - **Targets:** `packages/provegate/src/core/run/prompts.ts::assertResolved`,
     `packages/provegate/prompts/PLACEHOLDERS.md`

4. **FR-4**: `gate init --prompts` writes the rendered store. Writes are `wx` and
   additive-only, matching the existing init contract: an existing path is reported as
   skipped, never overwritten or deleted. `--prompts` composes with `--practices` and works
   without it. `gate init --dry-run --prompts` prints the plan and writes nothing.
   The starter config it writes sets `templates.prd` to the **rendered** PRD template, so
   `gate new` reads the store rather than falling back to the package copy
   (`core/run/new.ts:170`, `defaults.ts` `templates.prd: ''`). Without that rewiring the
   render would produce a second PRD template nobody reads, which is the drift this PRD
   exists to remove. An existing config is not rewritten — `--prompts` on a repository that
   already has one reports the required `templates.prd` value instead of editing it.
   - **Targets:** `packages/provegate/src/core/run/init.ts::planPrompts`,
     `packages/provegate/src/core/run/init.ts::starterConfig`,
     `packages/provegate/src/core/run/init.ts::runInit`,
     `packages/provegate/src/cli.ts::runInit`

5. **FR-5**: `renderAdapters(config)` emits one adapter per configured tool, each carrying a
   **path and no protocol prose**: `.claude/commands/prd-<phase>.md` (one per phase,
   instructing the agent to read the rendered protocol and follow it verbatim),
   `.cursor/rules/prd-workflow.mdc` (front-matter `globs` covering the four artifact
   directories from `config.dirs.artifacts`, body limited to the phase-to-path table), and
   `AGENTS.md.provegate.snippet` for Codex. A test asserts every adapter body is a pointer:
   no line of a rendered adapter appears verbatim in any phase protocol other than a path.
   - **Targets:** `packages/provegate/src/core/run/prompts.ts::renderAdapters`,
     `packages/provegate/src/core/run/prompts.ts::ADAPTERS`

6. **FR-6**: The Codex adapter is a **snippet, never a write** to `AGENTS.md`. `planPractices`
   states that agent-entrypoint files are deliberately absent from the pack so an existing
   entrypoint is never touched or shadowed; that invariant holds unchanged for `CLAUDE.md`,
   `AGENTS.md` and `.cursor/rules/brain.mdc`. The invariant is **narrowed, not broken**: a
   file at a provegate-namespaced path the adopter does not own (`.claude/commands/prd-*.md`,
   `.cursor/rules/prd-workflow.mdc`) is a generated adapter, not an entrypoint. The
   distinction is written into the `planPractices` comment and into the ADR, because the
   current comment reads as a blanket rule and a reader who only has the code must not
   conclude the rule was abandoned.
   - **Targets:** `packages/provegate/src/core/run/init.ts::planPractices`,
     `packages/provegate/practices/shims/AGENTS.md.snippet`,
     `packages/provegate/practices/NEXT_STEPS.md`,
     `_brain/adr/ADR-0002-agent-protocol-delivery.md`

7. **FR-7**: The store carries `<prompts.dir>/provegate.lock.json`: package version, and for
   every rendered path the hash of the render that produced it. A file whose on-disk bytes
   differ from its ledger hash is a divergence. A divergence is accepted **only** as an
   `exceptions` entry naming the exact path, an `owner` from `config.owners`, a `reason`,
   and a `reviewBy` date. An entry that is expired, that names a path the render no longer
   produces, or that names a path whose bytes now match the render again is a **failure, not
   a silent pass** — an allowlist that never expires becomes a permanent bypass.
   - **Targets:** `packages/provegate/src/core/run/prompts.ts::readLedger`,
     `packages/provegate/src/core/run/prompts.ts::writeLedger`,
     `packages/provegate/src/core/run/prompts.ts::reconcile`,
     `packages/provegate/schemas/prompts-lock.schema.json`

8. **FR-8**: `gate doctor --prompts` re-renders in memory and reports per file: `match`,
   `diverged`, `excepted`, `missing`, `orphan`. Exit is non-zero on any `diverged`,
   `missing`, `orphan`, or invalid exception. A repository whose config declares `prompts`
   and whose store directory is **absent** exits non-zero with that named reason — the check
   must not treat a missing file as nothing to check. `--json` emits the same report as
   structured output, matching the existing `--memory` shape.
   - **Targets:** `packages/provegate/src/cli.ts::runDoctor`,
     `packages/provegate/src/core/run/prompts.ts::promptsDoctor`

9. **FR-9**: The check is wired to an executing surface, both here and in the pack: a
   `verify:prompts` script in `package.json`, membership in the `verify:workflow` bundle,
   a step in the CI hygiene job, and — for adopters — `practices/verify/verify-prompts.mjs`
   with its `PACK_MAP` entry and its row in the packed bundle's `CHECKS`. A registered check
   with no executing surface, or an on-disk check with no registration, fails the wiring
   audit; this FR is complete only when `gate check --wiring` is green with it present.
   - **Targets:** `package.json`, `scripts/verify/verify-prompts.mjs`,
     `packages/provegate/practices/verify/verify-prompts.mjs`,
     `packages/provegate/practices/verify/verify-workflow.mjs`,
     `.github/workflows/ci.yml`

10. **FR-10**: The Phase 3 self-granted autonomy exception becomes configuration. The
    sentence at `prompts/phase-3-task-generator.md:92-94` ("Exception: in
    autonomous-execution mode, …") is replaced by a `{{AUTONOMY_MODE}}` block that renders
    the human-gated text when `prompts.autonomy` is `human-gated` and the documented
    exception when it is `autonomous`. `{{AUTONOMY_MODE}}` is registered in
    `PLACEHOLDERS.md` with its `workflow.config` mapping. **Precondition:** the
    corresponding snapshot file under
    `docs/research/provegate-bootstrap/source-snapshot/prompts/` is read first; where the
    snapshot's wording differs, the snapshot wins and this FR reduces to rendering the
    snapshot's text under the token. Method content is never authored here.
    - **Targets:** `packages/provegate/prompts/phase-3-task-generator.md`,
      `packages/provegate/prompts/PLACEHOLDERS.md`,
      `packages/provegate/prompts/orchestration-runner.md`

11. **FR-11**: `AGENT_BOOTSTRAP` gains the proceed rule beside the stop rules: during
    Phases 4–7 the only legitimate stops are the enumerated stop-and-ask checkpoints and a
    failed gate; every other decision is the agent's and is recorded in the task file's
    Deferrals & Decisions rather than escalated. The clause lands in **both** copies — this
    repository's `AGENT_BOOTSTRAP.md` and the shipped
    `practices/templates/AGENT_BOOTSTRAP.template.md` — and a test asserts the two carry it,
    because a rule corrected in one copy and left stale in the other is this repository's
    most frequently observed defect.
    - **Targets:** `AGENT_BOOTSTRAP.md`,
      `packages/provegate/practices/templates/AGENT_BOOTSTRAP.template.md`,
      `packages/provegate/test/practices-pack.test.ts`

12. **FR-12**: This repository consumes its own output. `.provegate/`, `.claude/commands/`
    and `.cursor/rules/prd-workflow.mdc` are generated by the built CLI and committed, and
    `workflow.config.json` gains the `prompts` block that produced them. A check asserts the
    committed render equals a fresh render. That check runs from `scripts/verify/`, **not**
    from a package test: a `provegate#test` task hashes package files, the rendered store
    lives outside the package, and a cached green would replay while the store drifted.
    - **Targets:** `workflow.config.json`, `.provegate/**`, `.claude/commands/**`,
      `.cursor/rules/prd-workflow.mdc`, `scripts/verify/verify-prompts.mjs`

13. **FR-13**: `gate init --practices` installs the protocol store and adapters for
    adopters. `PACK_MAP` gains the entries, `pack-manifest.json` and the pack-drift ledger
    reconcile against them, and `NEXT_STEPS.md` names the new store, the adapters, and
    `gate doctor --prompts` in the adopter's first-run sequence. `verify:pack-drift` is
    green with the additions on both sides.
    - **Targets:** `packages/provegate/src/core/run/init.ts::PACK_MAP`,
      `packages/provegate/test/pack-manifest.json`,
      `packages/provegate/practices/NEXT_STEPS.md`,
      `packages/provegate/test/practices-pack.test.ts`

## 5. Non-Goals (Out of Scope)

- **Migrating repositories that already installed the pack.** `gate init` is additive-only
  by explicit design and never overwrites; an adopter holding an older
  `AGENT_BOOTSTRAP.md` does not receive FR-11's clause. Stated here rather than left to be
  discovered — the migration path is separate work.
- **A machine-checkable Phase 3 "Go" gate.** Recording the human approval as state and
  refusing a task file without it is state-and-gate work, not content delivery. It reuses
  the operator-acceptance shape and belongs in its own work item.
- **An agent driver for Phases 4–7.** `orchestration-runner.md` names the driver half as
  living in a workflow tool or parent agent, and nothing implements it here. Whether one is
  needed should be measured after this PRD lands, not assumed before.
- **Consolidating the three duplicated method rules.** PRD-024, PRD-025 and PRD-026 own
  that; this PRD adds no second implementation of an existing gate.
- **Rewriting phase-protocol method content.** FR-10 introduces exactly one token and
  changes no rule. Every other byte of `prompts/` is traceable to the source snapshot and
  stays so.
- **A prompts registry, marketplace, or remote fetch.** The store is rendered from the
  installed package. Nothing in this PRD reaches the network.

## 6. Acceptance Criteria (Gherkin Style)

- **Given** a scratch repository built by `gate init --practices --prompts`, **When** its
  agent reads the Phase 3 adapter, **Then** it reaches a rendered protocol whose STOP rule
  and file paths are resolved for that repository.
- **Given** `prompts.values` omits `{{ARCHITECTURE_DOC}}`, **When** the render runs,
  **Then** it refuses naming that token and the key that supplies it, and writes no file.
- **Given** an existing `AGENTS.md`, **When** `gate init --prompts` runs, **Then** the file
  is byte-identical afterwards and the Codex adapter is emitted as a snippet.
- **Given** a rendered file edited by hand with no ledger exception, **When**
  `gate doctor --prompts` runs, **Then** it exits non-zero naming that path.
- **Given** a ledger exception whose `reviewBy` has passed, **When** the check runs,
  **Then** it fails for expiry, not for content.
- **Given** a ledger exception naming a path the render no longer produces, **When** the
  check runs, **Then** it fails as an orphan rather than passing on a path nobody renders.
- **Given** `prompts` is configured and the store directory does not exist, **When** the
  check runs, **Then** it exits non-zero; it does not report "nothing to check".
- **Given** a repository initialised with `--prompts`, **When** `gate new` runs, **Then** it
  reads the rendered template from the store, not the package copy.
- **Given** the store directory, **When** its contents are listed, **Then** every path
  except `provegate.lock.json` is reproducible by the render, and `workflow.config.json` is
  not among them.
- **Given** `prompts` is absent from the config, **When** every command in this PRD runs,
  **Then** behaviour is byte-identical to the pre-PRD build.
- **Given** `prompts.autonomy` is `human-gated`, **When** the Phase 3 protocol renders,
  **Then** it contains no self-assessable exception to the STOP rule.

## 7. Technical Considerations

### Architecture

**The store is a build output, and that is what makes it checkable.** Rendered content is a
pure function of the installed package version and `workflow.config.json`. The ledger
therefore does not need to be an independent source of truth — it records what the render
produced, and the check recomputes rather than trusts. This is the one design property that
keeps a fourth copy layer from becoming a fourth drift surface.

**Adapters carry a path and nothing else.** Three adapters plus a tool-neutral store is
four places a phase rule could be stated. It is stated in one, and FR-5's test enforces
that the other three contain no protocol prose. The repository's most repeated defect is a
rule corrected where it is owned and left standing where it is restated; the way not to
have that problem is not to restate.

**Scope is wide, deliberately, and the split line is pre-drawn.** Thirteen FRs across the
config surface, the installer, the CLI, shipped method content, the pack, and this
repository's own agent configuration. PRD-023 was superseded for exactly this shape, and
its diagnosis was size rather than care. If Phase 2 scores this below threshold on scope,
**the split is FR-7, FR-8 and FR-9 out as a follow-up** — the ledger, the doctor check and
its wiring — leaving a generated-not-edited store that a re-render can always reproduce.
That fallback is stated now so a later round is not designed under pressure.

**Prerequisites and serialization.** PRD-026 declares `core/run/init.ts`, `cli.ts`,
`practices/NEXT_STEPS.md`, `practices/templates/AGENT_BOOTSTRAP.template.md`,
`test/init.test.ts` and `test/pack-manifest.json` in its Conflict Surface — six paths this
PRD also claims. The collision is additive-versus-deletion rather than semantic (this PRD
adds `PACK_MAP` entries; PRD-026 removes different ones), but they are modify-in-place
files and the repository runs one serialized merge channel per package. This PRD is smaller
and PRD-026 is already gated behind PRD-025, so the intended order is **this PRD first,
PRD-026 absorbing its pack entries**. PRD-024 targets `core/gates/prd-ready.ts` and does not
overlap, so the two may run concurrently. **Re-run `gate queue` before Phase 3 rather than
trusting this paragraph** — it has gone stale twice in this repository within hours of
being written.

**Blast radius.** `core/config/load.ts` runs `deepMerge(DEFAULT_CONFIG, parsed)` before
validation, so a partial `prompts` object arrives carrying default siblings; validation must
be written against the merged shape, not the parsed one. Configured paths outside `memory.*`
have historically had no containment at all, which is why FR-1 specifies the escape check
explicitly and specifies realpath on both sides.

### Dependencies

- No new runtime dependency. `packages/provegate` takes zero, permanently.
- PRD-025 and PRD-026 are **not** prerequisites; the serialization above is a merge-order
  constraint, not a dependency.
- Nothing here reaches the network, and nothing adds a push code path.

## Memory Inputs

Records from the memory index this work item considered, each with a disposition and a
rationale. `applied` — the record changed this work item's shape. `reviewed` — it was read
and found not to change it, but is close enough that a reader deserves to know it was
considered. `not-applicable` — its watch or subject matched, and it does not apply here.
A rationale is required in every form, including `none`: an unreasoned `none` is the
ceremonial answer this contract exists to prevent.

Required in a memory-enabled repository, alongside Memory Outputs below.

  It is the reason FR-5 forbids protocol prose in adapters and the reason FR-11 lands the
  proceed rule in both `AGENT_BOOTSTRAP` copies with a test. A delivery mechanism that
  restates rules per tool is this record's failure mode built as a feature.
- applied: `docs-outlive-the-gate-they-promise` — its watch covers `AGENT_BOOTSTRAP.md`,

## 12. DO NOT (Anti-Patterns)

Explicit forbidden moves for this PRD. Catches drift the agent might otherwise
rationalize.

- DO NOT introduce `any`; use `unknown` + narrowing.
- DO NOT touch paths outside the Conflict Surface without recording the decision.
- DO NOT write protocol prose into an adapter. An adapter carries a path. The moment a
  phase rule is stated in two places, the delivery mechanism has recreated the defect it
  exists to remove.
- DO NOT overwrite, reorder, or append to `CLAUDE.md`, `AGENTS.md`, or
  `.cursor/rules/brain.mdc`. The Codex adapter is a snippet the adopter pastes.
- DO NOT move, copy, or emit `workflow.config.json` into the store. It is the render's
  input, it is hand-edited, and it is a control artifact the runner revalidates against
  base. The store holds generated output only; one hand-edited file inside it turns the
  ledger's question from total into partial.
- DO NOT render a template without giving it a reader. A rendered `prd-template.md` that
  `config.templates.prd` does not point at is a second copy of the artifact this PRD exists
  to stop duplicating.
- DO NOT author method content. FR-10 introduces one token; any wording that is not
  traceable to the source snapshot fails critical rule 4, whoever it reads better to.
- DO NOT let the render read the clock, the environment, or the network. It is a pure
  function of the package and the config, and the ledger check depends on that.
- DO NOT make an absent store, an unreadable ledger, or an unparseable exception pass
  quietly. Each fails by name; a check that skips is worse than no check because it reports
  green.
- DO NOT let a ledger exception live without an expiry. An allowlist that cannot go stale
  is a permanent bypass with a comment attached.
- DO NOT verify FR-12 with a package test. The rendered store is outside the package's
  turbo inputs and a cached green will replay while the store drifts.
- DO NOT change behaviour for a repository whose config omits `prompts`. Every command must
  be byte-identical to the pre-PRD build in that case, and a test must hold that line.
- DO NOT add a runtime dependency to `packages/provegate`, and DO NOT add a code path that
  reaches a git remote.
