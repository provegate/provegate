## 1. Introduction / Overview

Roadmap Phase B. Extract the two config chokepoints of the parent workflow —
`prd-state-utils.mjs` (524 LOC, ~60 importers) and `lib/base-branch-policy.mjs` (44 LOC) —
into a typed `WorkflowConfig` surface, and port the state SSOT (build/sync/query) and the
agent-lock lease model (lease + zero-dep glob engine + path-conflict detection) into
`packages/provegate/src/core/{config,state,locks}`. This unblocks the 33 P-classified
scripts downstream (inventory §1) and makes this repo the first consumer: on completion,
`gate status` and `gate queue` report on this very PRD.

Extraction rules (binding, from `source-snapshot/MANIFEST.md`): G-files port as-is,
P-files get their Emofy values lifted into config, no personal names, no Turkish strings,
English-only package content.

## 3. User Stories

### Primary User: workflow operator (repo owner running gated agents)

#### User Story 1

```
As a workflow operator,
I want workflow state derived from the artifact tree by one command,
so that queue/active/next decisions never rely on an agent's memory of what is in flight.
```

**Acceptance Criteria:**

- [ ] `gate status` rebuilds state from `_prds|_readiness|_tasks|_docs` and writes `_state/prds.json`.
- [ ] `gate queue --json` emits machine-readable ready/in-flight/blocked/in-review sets.
- [ ] Both commands work from a linked git worktree: the state snapshot is checkout-local
      (each checkout scans its own artifact tree — source parity); only lock operations
      resolve to the main checkout via `mainRepoRoot`.

#### User Story 2

```
As a workflow operator running parallel agents,
I want declared conflict surfaces checked mechanically against active leases,
so that two agents can never hold overlapping write-ownership of source paths.
```

**Acceptance Criteria:**

- [ ] A lock with malformed shape fails validation with a per-field issue list.
- [ ] Two active execution-phase locks with overlapping materialized globs are reported as a conflict.
- [ ] Shared append-only manifests never produce false conflicts.

#### User Story 3

```
As an adopter with a different repo layout,
I want every directory name, status word, branch name, and id pattern to come from config,
so that the tool works without adopting the parent project's conventions.
```

**Acceptance Criteria:**

- [ ] `workflow.config.json` at repo root overrides any default; absent file = pure defaults.
- [ ] Invalid config fails loud with path-tagged errors (e.g. `dirs.artifacts.prd: must be a string`).
- [ ] No default value contains a personal name or Turkish string.

## 4. Functional Requirements

Each FR carries the exact target paths the implementing agent will touch.
All new code TypeScript strict, ESM, node ≥22 builtins only.

1. **FR-1 — Config types + defaults**: `WorkflowConfig` interface tree covering:
   `dirs` (artifact dirs + prefixes + lifecycle subdirs `wip|completed|deferred` + state dir +
   locks dir + state file), `idPattern` (`{ prefix, width }`, default `PRD`/3), `statusVocab`
   (canonical statuses, alias→canonical map, active set, implemented set), `branches`
   (protected bases, default base, feature-branch template, direct-commit allowed
   prefixes/files — from `base-branch-policy.mjs`), `commands` (tool-agnostic names:
   checkTypes/lint/test/build), `owners` (acceptance owners, default `["owner", "operator"]`),
   `worktree` (`{ dir }`, default `.worktrees`), `executionPhases` (default
   `["Phase 2b", "Phase 3", "Phase 4", "Maintenance"]`), `sharedAppendOnly` (append-only
   manifest list). `DEFAULT_CONFIG` mirrors the source scripts' values minus Emofy-isms.
   - **Targets:** `packages/provegate/src/core/config/types.ts`, `packages/provegate/src/core/config/defaults.ts`, `packages/provegate/src/core/config/index.ts`
2. **FR-2 — Config load + validate (hand-rolled, zod-free)**: `findRepoRoot(cwd)` (walk up to
   `workflow.config.json` or `.git`; throws a clear error when neither is found), `loadConfig(cwd)`
   (read + deep-merge over defaults — plain objects merge recursively, arrays and scalars
   replace wholesale), `validateConfig(value): ConfigIssue[]` with `path`/`message` per issue;
   loader throws an aggregate error listing all issues. Unknown keys are issues (typo guard).
   - **Targets:** `packages/provegate/src/core/config/load.ts`, `packages/provegate/src/core/config/validate.ts`
3. **FR-3 — Markdown/artifact parsers**: port `stripMarkdown`, `getMetaValue`, `getTableValue`,
   `sectionAfter`, `findMarkdownTable`, `writeTableValue`, `countTaskChecks`,
   `countOperatorHandoff`, `declaredGlobs` (Conflict Surface parser) as pure functions;
   `parseArtifactName` + `listMarkdownFiles` driven by config `idPattern`/`dirs`.
   - **Targets:** `packages/provegate/src/core/state/markdown.ts`, `packages/provegate/src/core/state/artifacts.ts`
4. **FR-4 — Status normalization**: port `normalizeStatus` (alias map + annotated-status head
   matching) and `normalizeAutonomousClose` (placeholder-pipe → null, safer-value-wins),
   both reading vocab from config, not module constants.
   - **Targets:** `packages/provegate/src/core/state/status.ts`
5. **FR-5 — State build + persist + CLI**: port `buildPrdState` (collect artifacts → records
   with status/cyclePhase/autonomousClose/readiness/task/summary fields, sorted, schemaVersion 1),
   `readCurrentState`/`writeState`, `mainRepoRoot` (git `--git-common-dir`, worktree-stable).
   Wire `gate status` (rebuild + write snapshot + one-line-per-record summary + panel metrics)
   and `gate queue [--json]` (rebuild + queue view) in the CLI router, replacing their stubs.
   `init|new|check|open|run|land` remain stubs; `push` refusal byte-identical.
   - **Targets:** `packages/provegate/src/core/state/build.ts`, `packages/provegate/src/core/state/io.ts`, `packages/provegate/src/cli.ts`
6. **FR-6 — State queries**: port `isImplemented`, `latestImplemented`, `latestByStatus`,
   `statusPanelMetrics` (English labels), `getActiveRecords` (per-record done-check, no
   high-water-mark), `getReadyRecords` (approved/PASS, unlocked, score-then-number sort),
   `buildQueue` (ready + readyOverlaps + inFlight + blocked + inReview, `resume` flag).
   - **Targets:** `packages/provegate/src/core/state/query.ts`
7. **FR-7 — Lock lease model**: port `locksDir` (main checkout), `lockPathFor`,
   `ensureLocksDir`, `migrateWorktreeLocks`, `listLockFiles` (parse-error tolerant), plus
   `validateLock(lock): string[]` — the required-field/shape checks from
   `verify-agent-locks.mjs` (schemaVersion 1|2, non-empty `touchedFiles`, worktree-prefix
   check against config `worktree.dir`, valid/unexpired `expiresAt`, `validateOwnedPaths`)
   returned as issue strings, and `findLeaseConflicts` (pairwise `touchedFiles` overlap of
   unexpired locks).
   - **Targets:** `packages/provegate/src/core/locks/lease.ts`
8. **FR-8 — Glob engine**: port `globToRegExp` byte-equal semantics — `**` crosses `/`
   (collapsing the following slash), `*` single-segment, `?` one non-slash char, full
   metacharacter escaping, anchored both ends. Zero dependencies.
   - **Targets:** `packages/provegate/src/core/locks/glob.ts`
9. **FR-9 — Path-conflict detection**: port `trackedFiles` (git ls-files), `materialize`
   (glob expansion minus config `sharedAppendOnly`), `structuralOverlap` (normalized
   prefix-nesting for zero-materialization globs), `findConflicts` (active execution-phase
   locks with declared surfaces, pairwise), `candidateFromPrd` (id validated against config
   `idPattern`, searched in config artifact dirs, `declaredGlobs` reuse, stamped
   execution-phase), `candidateConflicts` (candidate vs rivals, own lock excluded).
   The `GRANDFATHERED` set is NOT ported (fresh project — empty by construction).
   - **Targets:** `packages/provegate/src/core/locks/conflicts.ts`
10. **FR-10 — Generalized schemas**: port `agent-lock.schema.json`, `prd-state.schema.json`,
    `acceptances.schema.json` into `packages/provegate/schemas/`: neutral `$id`
    (`https://provegate.dev/schemas/...`), titles/descriptions de-Emofy'd and English,
    id-pattern documented as the config default (`^PRD-[0-9]{3}$`) with a note that runtime
    validation derives the pattern from config. `_state/schema/README.md` updated to point
    at the package schemas as source of truth.
    - **Targets:** `packages/provegate/schemas/agent-lock.schema.json`, `packages/provegate/schemas/prd-state.schema.json`, `packages/provegate/schemas/acceptances.schema.json`, `packages/provegate/schemas/README.md`, `_state/schema/README.md`
11. **FR-11 — Programmatic exports**: `src/core/{config,state,locks}/index.ts` re-export the
    public API; `src/index.ts` exposes it; tsup build emits types; `core/run` and
    `core/gates` stubs untouched.
    - **Targets:** `packages/provegate/src/core/config/index.ts`, `packages/provegate/src/core/state/index.ts`, `packages/provegate/src/core/locks/index.ts`, `packages/provegate/src/index.ts`

## 6. Acceptance Criteria (Gherkin Style)

- **Given** a repo with no `workflow.config.json`, **When** `loadConfig` runs, **Then** it
  returns `DEFAULT_CONFIG` values and `gate status` works against the default tree layout.
- **Given** a config file with `{"idPattern": {"prefix": "TASK", "width": 4}}`, **When**
  artifacts named `task-0042-*.md` exist under the configured dirs, **Then** state records
  carry id `TASK-0042` and `candidateFromPrd("TASK-0042")` resolves.
- **Given** a config file with an unknown key or wrong-typed field, **When** `loadConfig`
  runs, **Then** it throws one aggregate error listing every issue with its config path.
- **Given** this repository, **When** `node packages/provegate/dist/cli.js status` runs,
  **Then** exit 0 and the output contains `PRD-001` with status `Draft` (or later), and
  `_state/prds.json` exists with a `records[]` entry for PRD-001.
- **Given** two unexpired locks in execution phases whose `ownedPaths` materialize to a
  shared tracked file, **When** `findConflicts` runs, **Then** the pair is reported with the
  shared paths; **Given** the same overlap only via `sharedAppendOnly` files, **Then** no
  conflict is reported.
- **Given** a lock missing `expiresAt` or with non-array `touchedFiles`, **When**
  `validateLock` runs, **Then** each defect appears as a distinct issue string.
- **Given** any CLI invocation, **When** `gate push` runs, **Then** stderr is
  `No. Push is yours.` and exit code is 1 (unchanged).

## 7. Technical Considerations

### Architecture

- **Config over hardcode**: every module takes `WorkflowConfig` (or a slice) as an explicit
  parameter; only the CLI layer calls `loadConfig`. No module-level mutable config singleton.
- **Repo-root discovery** replaces the source's `import.meta.url`-relative `REPO_ROOT`
  (invalid for an installed package): walk up from `cwd`; `mainRepoRoot` keeps the
  git-common-dir derivation so locks/state live on the main checkout from any worktree.
- **State file is a generated snapshot** of the artifact tree (artifacts are the SSOT).
  `gate status`/`gate queue` always rebuild fresh, then persist — no stale-read mode, no
  separate sync command.
- **Error style**: library functions return issue lists or throw typed errors; only the CLI
  maps to `process.exitCode`/stderr (the source's `fail()`/`ok()` stay CLI-side).

### Dependencies

- Runtime: none (node builtins + `git` subprocess). Dev: existing (vitest, tsup, typescript).

### Database Changes

- None. File formats: `_state/prds.json` (snapshot), `_state/locks/*.json` (leases).

### API Changes

- CLI: `gate status`, `gate queue [--json]` become real; everything else unchanged.

## 12. DO NOT (Anti-Patterns)

- DO NOT introduce `any`; use `unknown` + narrowing.
- DO NOT add a runtime dependency — if one seems needed, stop and surface it.
- DO NOT add any code path that pushes to a git remote, or weaken the `push` refusal.
- DO NOT hardcode parent-project values (directory names, `development`/branch names, Turkish
  labels, PRD-number thresholds, `@emofy/*`, pnpm script names) — every such value flows
  through `WorkflowConfig`.
- DO NOT port the `GRANDFATHERED` lock set, PRD-number grandfather thresholds, or any
  personal name (`rayvaz` allowlist value, author names) into package code or defaults.
- DO NOT let queries filter by a serial high-water-mark (the bug PRD-312 removed) — the
  per-record done-check is the ported semantic.
- DO NOT make network calls or add telemetry.
- DO NOT spawn git through a shell — `execFile`-style array-argument invocation only (the
  source's `execFileSync` discipline; no `exec`, no string interpolation into commands).
- DO NOT fabricate prompts/templates/method content — out of scope until Phase D.
