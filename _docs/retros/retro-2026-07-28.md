# Retro — 2026-07-28

First retrospective. Period covered: the practices import (2026-07-24) through today —
26 PRDs closed, PRD-023 superseded, the PRD-029 prompt-store wave opened, and the first
independent confirmation rounds on PRD-024/025. Themes below are cross-PRD by
construction: each one recurs in at least three work items and none is owned by any
single PRD.

## 1. The restatement defect is this period's dominant failure class

`a-rule-corrected-survives-where-it-is-restated` was written after five instances and
extended after four more. The count across the period is now at least eight distinct
instances spanning PRD-021, PRD-023, and the PRD-029–032 chain — and **four times the
fix for one instance created the next** (the sharpest: PRD-030's non-binding banner,
scoped to §4 while the removed design was restated in four other sections — the pattern
applied to the fix for the pattern). Today's confirmation rounds found live instances in
both documents scored: PRD-024's DO NOT still says "three existing fixtures" where its
own FR-1 counts four, and PRD-025's Goals still say "two hardcoded paths" where its own
metric row says three.

What worked, measured twice: **rewriting the review brief from "hunt for defects" to
"sweep every restatement of the rule that just changed"**. PRD-021 iteration 14 moved
the score 0.10 with a sweep where four hunt-rounds had moved 0.01–0.18 each; PRD-029
went 6.03 → 8.35 on three sweep rounds after the scope cut. The mechanism matches the
cause: an author corrects a rule in the section that owns it and does not, unprompted,
re-read the other five sections that restate it. No lint can see a semantic restatement;
the brief is the countermeasure we have. **Keep sweep-briefs as the default shape for
any post-remediation round.**

## 2. Protocol instructions that are not in context do not execute

PRD-029's readiness sat in the 4–5.9 band for five consecutive rounds while every round
applied the 6–7.9 band's action. The scoring protocol prescribed "return to Phase 1"
from round one; the sessions running the rounds had the scorecard in context and the
protocol's Score Interpretation table not. The same asymmetry is PRD-029's own subject —
ten phase protocols shipped in the package and none installed where an agent's reader
is pointed, while `AGENT_BOOTSTRAP.md`'s stop-and-ask list is always loaded with no
counterweight. Skipping prescribed actions and inventing extra caution are one defect:
**agents execute the context they are handed, not the corpus they theoretically have.**
The structural fix is in flight (the PRD-029 prompt store, then the 030–032 chain);
until it lands, any session applying a scored protocol should load the protocol file,
not its summary.

## 3. Measurements go stale in hours; keep the command, not the number

Recorded instances: PRD-024's wip-corpus count changed three times during its own
readiness rounds; `gate queue` overlap notes went stale twice within one day
(2026-07-25, recorded on the board); PRD-021's close invalidated PRD-024's motivating
measurement (its only live allowlisted-command instance was in PRD-021's Notes cell —
archived with it) and obsoleted PRD-025's serialization notes, both within a day; and
the board's own Current state row said "Last shipped PRD-021" while three later closes
had happened. Line-number citations age the same way — today's rounds found
`prd-ready.ts` and `validate.ts` anchors drifted by a landed PRD, harmlessly but
consistently.

The adaptation that worked is already in PRD-024's text: state the measurement's
**method and date, "deliberately not fixed as a number"**, and instruct re-measurement
at claim time (`re-run gate queue rather than trusting this paragraph`). Extend that
habit: a document's measurement is a snapshot; the durable artifact is the command that
reproduces it.

## 4. Independence keeps proving itself — and its cost curve needs an owner

The measured gap stands: two self-scored rounds returned PASS-band with zero [P1]s where
one independent round returned four per PRD, and "who writes the brief changes what is
found" (PRD-029 iteration 5) has not been contradicted since. Today added a smaller
datum: a confirmation round on an *unchanged* document still paid, because the
environment had moved under it (a landed PRD, a reddened corpus) and nobody had looked.

The cost side: PRD-018's Phase 6 took 26 rounds, PRD-029's readiness eight, PRD-024 has
had seven. The bootstrap doc promised threshold recalibration "after the first ~10
scored candidates"; the corpus passed 17 scored items and the recalibration has not
happened and has no owner. **Action: owner schedules the calibration pass** — what the
bands mean, what a confirmation round costs versus catches, and whether the 8.0 bar is
priced correctly for `infra`-class items.

## 5. Unenforced rituals do not run

This file is the evidence: every enforced ritual ran on every close (durable artifacts,
memory contract, value sweep — all gated), and the one unenforced ritual ran zero times
in 26 closes. That is `gate-wire-or-delete` applied to process, and the repo already
knew it — the deferral board only works because `verify:deferred` enforces its cap (14
of 15 rows today; the cap did successfully force PRD-035 out of a deferral row).
**Decide the retro's mechanism**: either a cadence check in the verify library (warn
when the newest `_docs/retros/` file is older than N closes) or an explicit owner
trigger at wave boundaries. An unwired intention is the thing this repository exists to
refuse.

## 6. All momentum is inward; the adoption surface is frozen

Every wave since the import has been method-internal (memory, governance, self-hosting,
prompt store). The only adoption-facing item in the queue, PRD-027, is unscored-low and
unclaimed; `main` is unpushed; org and npm publish remain open owner tasks; roadmap
Faz E (case study, whitepaper, launch) has zero started items. The inward work is not
waste — it compounds the launch story ("the tool built under its own gates, here are
the PRDs") — but the story has no audience until something is published. **Action:
owner decisions on push/org/npm; pull PRD-027 forward once PRD-024/025 are dispatched.**

## Postscript — captured while writing this retro

The scoring session that produced this file reproduced one of the themes on itself.
Its readiness note began "Updated at iteration 7; …" — and the state builder's
`getMetaValue` third pattern (`^Updated\s*:?\s*…`, colon optional, `state/markdown.ts:30`)
captured the rest of that sentence as PRD-024's `lastUpdated`, which the lexicographic-max
rule in `build.ts:129` then preferred over every real date. A reader whose span is wider
than its claim — `lint-must-name-the-span-it-judges`, the exact learning PRD-024 exists
to write — fired in the state builder while it recorded PRD-024's score. Reworded in the
artifact, filed as a deferral (2026-09-26). The method's rate of catching its own
failures on itself is the strongest evidence in this file.
