## Findings — round 2

| # | Sev | Finding | Resolution |

| 11 | LOW | **Limits row 2's new attribution is right; the mechanism it cites as proof is not.** `_docs/design/prompt-store-state-model.md:285` justifies the `mixed` class with "nothing in C1–C4 forbids write-temp-then-rename". Two problems, and the wording is lifted from my own round-1 finding, so this is my imprecision arriving in the document. (a) `rename(2)` **silently replaces** an existing destination — `fs.renameSync` included — so temp-then-rename is exactly the primitive that would break C1's "nothing is ever overwritten", which is the promise `init.ts:267-269` chose `wx` for ("no exists/write race can truncate a concurrently created file"). The constraint-safe staged primitive is `fs.linkSync`, which throws `EEXIST`. (b) Even with `link`, it buys nothing for *this* limit: the generated set spans three unrelated destination roots (`<dir>/`, `.claude/commands/`, `.cursor/rules/`), so no single rename or directory swap makes the **set** atomic, and set-level atomicity across them needs a durable journal — which is a manifest, which is the T7 decision, i.e. the design half of the row. What genuinely is implementation-side, and what the row can stand on instead: `initWorkspace` already holds the full path→content map before it writes anything (`init.ts:300-307`), so it could unlink its own just-created paths on an in-process write failure and shrink "partial set" to the hard-interrupt case alone, with no manifest and without touching an adopter's file. The `mixed` class, and the future item's freedom to report the gap, both survive on that reading. | open — non-blocking; replace the cited primitive, or point the cell at the in-process-rollback argument |
